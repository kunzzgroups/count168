## 四、客服 / 内部技术说明（不用发给用户）

### 这次真正修的是什么

**原因**：App 外壳（Capacitor）里有一个配置项 `android.captureInput` 被设成了 `true`。它会让 WebView 把给输入法用的"输入连接"换成 `BaseInputConnection(this, false)` —— 这是一个**假编辑器**：它把文字存在自己的缓冲里，而不是网页输入框里，并靠"兜底模式"把编辑转成合成按键事件再交给网页。

结果就是：输入法（尤其搜狗，会长时间持有组合输入）先把删除作用在自己的缓冲上，网页要等这批编辑被集中送出后才看到 → 用户感觉"第一次删除没反应、要多按几次、或者要等两三秒"。

**修复**：把该配置改成 `false`，WebView 恢复使用 **Chromium 自己的输入连接**（与在 Chrome 里输入走同一条路）。改动只有一行：`c168_mobile/app/capacitor.config.json`。

**同一个版本里还包含**（与删除键无关，但都是真实问题）：

- 备注等中文输入框原来是 React 受控输入（每次按键都会被重写）→ 改成不重写
- 搜索框在输入法组合期间就过滤中间状态 → 列表与输入框文字对不上；现改为始终跟随可见文字
- 搜索接口的旧响应可能覆盖新结果 → 已用请求序号 + 取消机制保证只显示最新查询的结果

### 还没做的部分（内部注意）

- **count168.site 与 www.count168.org 没有发布**：服务器上这两个域名**没有 `/app/` 下载页**（该路径返回的是 App 页面本身），org 的前端目录里也没有 `app/` 子目录。两份包已构建并验签，存放在 `c168_mobile/app/dist-apk/`，但**没有上传**（也没有可指向的页面）。若要给这两个域名的用户分发，需要先确定下载页放在哪里。
- **不要绕过出包脚本直接构建**：仓库里 `capacitor.config.json` 的默认域名是 `count168.site`，`build-apk-for-site.mjs` 会在出包时按目标域名临时改写并还原。直接跑 `gradlew assembleRelease` 出来的包会指向 site，用户会看到别家的数据。发布请用 `npm run release:apk com`（它会自动比对签名指纹，密钥不对就拒绝出包）。
